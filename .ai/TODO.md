# Sprint 04 Summary

Delivered: `/business/[slug]` — hero (name, category, featured/verified badges, share button), gallery, service areas, contact info (tel/mailto/website/address), opening hours (7 days + Closed), social links (Follow section) — each section independently omitted when its data is absent, never showing a broken/empty block. Per-business SEO metadata (title, description, Open Graph) and `LocalBusiness` JSON-LD structured data, generated by a pure, unit-tested function (`lib/services/structuredData.ts`).

Key decisions:

- **No `loading.tsx` for this route** — it calls `notFound()`, and Sprint 3 already proved a sibling `loading.tsx` breaks the 404 status code. Confirmed via curl that invalid slugs return real 404s.
- **Real placeholder image, not broken links.** The original sample data referenced per-business `.jpg` paths that didn't exist as files. Replaced with a single hand-authored, brand-colored SVG (`public/images/placeholder-business.svg`) referenced by every business, with "Photo coming soon" text — honest rather than pretending real photography exists. Required enabling `dangerouslyAllowSVG` in `next.config.ts` (scoped safely — it's a trusted, self-authored static asset, not user content).
- **No brand icons for social links** — lucide-react doesn't ship Facebook/Instagram/LinkedIn icons in this version. Used a generic link icon + platform name label instead (also more accessible than icon-only).
- Reused the existing `BusinessRepository.getBySlug()` / `CategoryRepository.getBySlug()` rather than adding new methods.

`npm run lint`, `typecheck`, `format:check`, `test` (29 unit tests), `test:e2e` (19 Playwright tests), and `build` all pass. Verified visually (desktop + mobile, 3 different businesses to exercise graceful degradation), keyboard tab order, heading hierarchy, valid JSON-LD via manual parse, and actual Share-button clipboard behaviour.

Full plan: `sprints/sprint-04-business-details/`.
